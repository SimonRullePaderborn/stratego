Unified Wavefront Design

The design has one lattice, one local rule and one operation, which is to clamp what is known or already decided and grow the rest. The same learner covers larger grids, moving targets, hidden targets with an observer, directed sensors and several drones to recharge, because each of those enters only as a declaration made by the environment.

Status

This is a specification. Parts marked measured rest on the 8×8 experiments in this repository. Parts marked not yet tested are proposals. The design has not been built or run as a whole.

§1The idea

The lattice has time as one of its three axes. At any moment it holds a window of time slices around the present. Slices behind the present hold facts, meaning what the sensors reported and where the drones actually went. Slices ahead hold the dream. For each kind of drone the system controls, the dream contains a tube that marks where those drones will be. For everything the system only observes, it contains a forecast. The present is the front between facts and dream.

Every step repeats four actions.

  1. Clamp the newest facts into the lattice.
  2. Run the rule for a few iterations.
  3. Move each controlled drone to the reachable position where its tube is strongest, and clamp that choice as a commitment.
  4. Advance the simulator and slide the window by one slice.

The lattice keeps its state from step to step. A plan made at one step is still there at the next unless new facts contradict it. not yet tested

Two rules carry over from the earlier work. Drones are steered by tubes, which are positions in space-time, and never by a field of arrows. Forecasts describe things the system does not control, and no action is ever read from a forecast.

§2The bitter-lesson contract

Sutton's bitter lesson says that methods which scale with computation, namely search and learning, end up ahead of methods that build in what their designers know. For this design that becomes five rules. Each one has a check.

  1. No domain concept in the learner. Battery, distance, meeting, escort, cone and heading are not named anywhere in it. Environments differ only through the declaration in §3. Check a text search of the learner's source.
  2. Every ability comes from search or learning. Each has a compute dial, listed in §10.
  3. More compute never hurts. More iterations, more clones or a longer window must not lower success. Check the three sweeps in §9. The rule trained so far fails this check: twice the iterations cost it 5 to 18 points measured. The persistent lattice and the randomised iteration counts exist to repair that.
  4. No exploration prior, curriculum, reward shaping or solution heuristic. Tasks are drawn uniformly. Selection uses return and nothing else.
  5. Every prior that remains is written down together with the test that could remove it (§11).

The learner knows an environment only through this declaration and four simulator calls.

  • reset(task, world) starts an episode. The task fixes what is visible at the start. The world seed fixes everything hidden or random.
  • step(actions) returns the observation, the reward and whether the episode is over.
  • peek(drone, action) returns that drone's own next state for one action. It looks one step ahead and gives no reward.
  • replay(actions) runs a recorded list of actions from the start.

A controlled drone always knows its own state. The battery is never part of any observation.

§4The lattice

The window holds P past slices, the present slice and F future slices, each the size of the grid. Two tensors live on it. The state S has C channels and persists from step to step. The clamped input X holds the facts and is rewritten only where something becomes known or decided.

Channel groupCountContentNon-zero in
seen (input)1A sensor covered this cell at this timePast and present
fact per type (input)Own-state alphabet sizeAn entity of this type and own-state is known to be here, because it was observed or because the system committed to itPast, present, and the slice just ahead while drones commit
identity (input)dThe entity's code vectorWherever a fact is

tube per controlled type (output)Own-state alphabet sizeWhere drones of this type will beRead in future slices
forecast (output)1 + alphabet sizes of observed typesWhich cells will be sensed, and what will be found thereRead in future slices

The rule has the form already trained, with wider layers.

x  = [ normalise(S), X ]                 per voxel; normalise acts across the C state channels
h  = relu( conv 3×3×3 (x) )              zero padding; the only place neighbours are seen
S  ← S + W3 · relu( W2 · h )             W2 and W3 act on one voxel at a time
tube, forecast = linear readouts of S    one voxel at a time

All weights are shared across voxels, slices and iterations. There are no coordinate channels, no pooling, no attention and no iteration counter.

§5Acting

start of an episode
    S ← 0, X ← 0
    clamp the first observation into the present slice
    run the rule K0 times

every step t
    for each controlled drone i, in a freshly shuffled order
        for each action a of drone i
            u[a]     ← sim.peek(i, a)                            the drone's own next state
            score[a] ← tube[type(i)][present + 1][u[a]]
        a_i ← argmax over a of  score[a] / τ + noise(i, t, a)    τ = 0: plain argmax, no noise
        clamp fact[type(i)][present + 1][u[a_i]] ← 1             the commitment
        run the rule k_c times
    observation, reward, done ← sim.step(a_1 … a_n)
    slide S and X one slice towards the past
    clamp the observation into the present slice                 replaces the commitments
    run the rule k_s times
  • The order is shuffled at every step. A drone that chooses later sees the commitments of the drones before it. This is the chain rule for a joint choice, and it assumes nothing about who should lead. not yet tested
  • Sampling noise enters in the argmax line only. With τ = 0 the protocol is deterministic.
  • One step costs n · k_c + k_s iterations of the rule for n controlled drones.
  • When the window slides, facts older than P steps leave the input. Anything still needed must by then be held in the state channels.
  • A diagnostic readout runs K0 iterations once and then follows the tubes with no further clamping. It measures how much of the plan the dream holds by itself.

§6Search

A strategy is one noise stream per controlled drone plus a temperature τ. The greedy strategy has τ = 0. A world is a seed for everything that is hidden or random. A clone is one strategy acting in one world with the protocol of §5.

for each task, drawn uniformly
    worlds     ← W seeds
    strategies ← the greedy one and M − 1 sampled ones
    for each strategy σ and world ω
        G[σ, ω] ← return of the clone (σ, ω)
    recombination, simulator only
        mix the drones' recorded action lists across clones
        replay every mix in all W worlds; each mix is one more strategy
    V[σ] ← mean of G[σ, ω] over ω
    best ← argmax V
    if V[best] > V[greedy]       keep best      search beat the current rule
    else if V[greedy] > 0        keep greedy    consolidate what already works
    else                         keep nothing
  • Every strategy meets the same worlds, so values are comparable.
  • When nothing is hidden or random, W = 1 and the rule reduces to keeping the best rewarded rollout, as in the measured system.
  • When something is hidden or random, the best single rollout is the luckiest one. Averaging over worlds before selecting removes the luck. The kept strategy is then imitated in all W worlds, including those where it earned nothing. A good way of looking for a hidden target is still right in the world where the target happened to be far away. not yet tested
  • Recombination costs simulator time only, and from the same samples it finds many more rewarded plans. measured
  • The population is flat. There is no tree, no value estimate and no backup.

§7Credit

A sparse reward says that a joint plan worked. It does not say whose behaviour made it work. The kept strategy is therefore run again with one drone lesioned: that drone acts uniformly at random for the whole episode, while all other drones act as before and react to what they now see.

credit[i] = clip( ( V[kept] − V[kept, drone i random] ) / V[kept], 0, 1 )   with K lesion runs per world
  • A drone that did not matter gets credit 0 and is not imitated. In an open-loop form this is what stopped the recharger from learning to stand still. measured
  • Because the other drones react to the lesion, a drone whose only contribution is information earns credit when the others fail without it. Replaying recorded actions cannot show that, since the recorded actions already contain what the informer found. not yet tested
  • For a recombined strategy the other drones replay their action lists.

§8Learning

There are two buffers. One holds the kept rollouts with their credits. The other holds a sample of all clones, whatever their outcome.

repeat
    take a batch of stored episodes
    replay each one: same task, same world, stored actions and commit order,
                     lattice run by the protocol of §5 with K0, k_c, k_s redrawn
    every n_bp steps
        loss ← tube loss + λ · forecast loss    on the slices ahead of the present
        back-propagate through the rule iterations of these n_bp steps only
        update the weights, detach the lattice state, continue the replay
tube loss = − Σ over drones i and future slices j of  credit[i] · log softmax( tube[type(i)][j] )[ u_i(j) ]
  • u_i(j) is the state drone i really had at that time. The softmax runs over all cells and own-states of the slice. Slices after the end of the episode carry no loss.
  • The forecast loss is the cross-entropy between the forecast in a future slice and what was observed there later. For fact channels it counts only cells that were sensed.
  • Tubes learn from kept rollouts only. Forecasts learn from every rollout, rewarded or not.
  • Iteration counts are redrawn for every replayed episode: K0 between half and twice the window length, k_c from 1 to 2, k_s from 1 to 4. This is what allows the counts to be raised at test time.
  • Tasks, grid sizes and numbers of entities are drawn from whatever the environment offers, in no particular order.

§9Evaluation and checks

  • Headline number. The greedy strategy, averaged over W worlds, on tasks that were never posed in training, with task seeds fixed in advance.
  • Dream-only readout where the whole world is visible, as described in §5.
  • Commit stride. Commit every 1, 2 or 5 steps, or never. The curve shows how much replanning the rule needs.
  • Compute sweeps for rule 3. Success against iterations at ×1, ×2 and ×4, against the dream length F, and against the number of strategies M.
  • Ablations. Credit off, with all weights 1. Recombination off. Forecast loss off. All drones commit at once.
  • Domain-term search for rule 1 over the learner's source.

Not yet tested

  • A lattice that keeps its state inside a sliding window.
  • The shuffled commit order.
  • Selecting strategies by their value over several worlds.
  • Closed-loop lesion credit, including credit for a drone that only gathers information.
  • The forecast outputs.
  • Training with independent noise and recombination. One older run without shared noise and without recombination reached 65.5% where the run with shared noise reached 75.4%.

Where it could fail

  • On large grids, long formation flights are found by independent noise only after the rule has learned to follow a partner on short tasks. If that transfer does not happen, shared noise returns as a dial with a known price.
  • Back-propagation through two steps may be too short to teach plans that depend on events far ahead.
  • Lesion credit costs lattice runs in proportion to the number of drones.

§13Build order

  1. Port the measured recipe to the declared interface on 8×8, with a window spanning the episode, W = 1, independent noise and recombination. Pass: at least the earlier 75% on tasks never posed in training.
  2. Add the persistent lattice and redrawn iteration counts. Pass: success does not fall when the iterations are doubled and quadrupled.
  3. Add the sliding window and train on grids from 8 to 16. Pass: 16×16 far above the 25% reached without retraining, and targets beyond 14 cells solved.
  4. Hide the target, add an observer, set W = 8. Pass: the observer's credit is above zero and success is higher than with a random observer.
  5. Give the observer a heading. Add further seekers.

Each stage keeps all earlier checks.
