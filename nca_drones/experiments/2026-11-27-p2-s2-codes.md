# Experiment card: 2026-11-27-p2-s2-codes

## Before the run

* **Phase and gate it serves:** phase 2, step 2 of the chain in `PROGRAMME.md` section 12.4.
* **Hypothesis (one sentence):** giving each drone a random one-hot code per episode, and reading its tube through
  that code instead of through a fixed channel per drone type, does not lower closed-loop success on the 2,000
  never-posed tasks, compared with step 1.
* **What would support it:** the closed-loop rate of this run (bf16, its own 2,000 never-posed tasks) is not below
  the rate of step 1 by more than max(2 s, 2 points), with s the standard deviation of the three rates of step 0
  (rule of section 12.4).
* **What would refute it:** a rate further below. Then the run is looked at on trajectories before step 3 is built
  on it.
* **The one thing that changes** relative to step 1: `--codes 1`. For every posed task, for every evaluation episode
  and for every learning sample, two different code numbers out of 16 are drawn, one for the seeker and one for the
  recharger. The seeker is drawn on input map 1 + its code, the recharger on map 17 + its code, the seeker's battery
  level on map 33 + the seeker's code; map 0 stays the target. The rule has 16 output maps, and a drone's tube is the
  output map of its code. Inputs go from 4 maps to 49, outputs from 2 to 16, weights from 39,858 to 117,856 (almost
  all in the first convolution). State width, hidden width, search, credit, shared noise, loss, evaluation sets and
  seed are those of step 1. A stored rollout is learned under freshly drawn codes each time it is sampled.
* **Also reported, with no threshold:** what the codes cost in learning speed (a reviewer's point: every code map has
  weights of its own): validation success after 100, 200, 300, 450, 600 and 900 rounds beside step 1; the seconds per
  round; the paired difference to step 1 on the 200-task test set.
* **Verification done on the cluster's CPUs first:** `test_sim.py`, which now ends with `test_codes`: 1,000 draws
  (always two different codes, every code occurring), the 49 maps of a hand-worked episode value by value, and the
  selection of a drone's own output map. Then a three-round smoke run with both switches.
* **How it runs:** one Docker container, CPU only, 16 cores, from `~/wf/runs/p2s2` filled from the Mac:
  `bash cluster/jobs/p2_old_recipe.sh p2s2_codes_s0 0 0.5 --battery 1 --codes 1`. It starts before step 1 has ended;
  if step 1 is not kept, this run is void and is repeated without `--battery 1`.
* **Commit:** the commit that holds this card, named in `~/wf/runs/p2s2/COMMIT`.
* **Cluster job ids:** container `wf-p2s2-s0`.   **Estimated GPU-hours:** 0 (CPU only; the first convolution is about
  three times larger, so several hours)
