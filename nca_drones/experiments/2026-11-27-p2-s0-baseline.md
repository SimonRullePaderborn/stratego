# Experiment card: 2026-11-27-p2-s0-baseline

## Before the run

* **Phase and gate it serves:** phase 2, step 0 of the chain in `PROGRAMME.md` section 12.4. It gives the baseline
  and the run-to-run spread against which every later step is judged.
* **Hypothesis (one sentence):** the measured 8x8 recipe (the settings of the stored run `v10`), trained again on the
  cluster with seeds 0, 1 and 2, reaches a three-seed mean of the closed-loop rate on the 2,000 never-posed tasks
  within 5 points of the stored 75.4%.
* **What would support it:** the mean of the three rates (bf16, closed loop, each run's own 2,000 never-posed tasks)
  lies between 70.4% and 80.4%.
* **What would refute it:** a mean outside that range. Then the recipe or the environment differs from the stored
  run, and nothing is built on it before that is understood.
* **The one thing that changes** relative to which earlier run: nothing relative to `v10` for seed 0 (same code, same
  flags, same PyTorch 2.15.0); seeds 1 and 2 differ in the seed alone. The 8x8 work had one seed per recipe.
* **Also reported, with no threshold:** whether seed 0 reproduces the stored run exactly (its counts, and the round
  of the chosen checkpoint, 851 in the stored run); the standard deviation and the range of the three rates; the
  time per round on this node.
* **What the result decides:** the spread s (standard deviation of the three rates) sets the rule for steps 1 and
  later: a step is kept when its closed-loop rate on its 2,000 never-posed tasks is not below the rate of the step
  before by more than max(2 s, 2 points). Two points is twice the binomial error of one such rate.
* **Verification done on the cluster's CPUs first:** `test_sim.py` in the run folder (the 8x8 code is unchanged
  since phase 0, where it passed).
* **How it runs:** three Docker containers, one per seed, CPU only (no GPU is visible to them), 16 cores each, from
  `~/wf/runs/p2s0` filled from the Mac (section 9.2). Each runs
  `bash cluster/jobs/p2_old_recipe.sh p2s0_shared_s<seed> <seed> 0.5`: the trainer with the flags of `v10`
  (`--threads 2`, 1,500-round schedule), stopped when round 900 is in its log; then `analyze.py --prereg` on the
  `best.pt` that exists at that moment, as `EVAL_PROTOCOL.md` prescribes.
* **Commit:** the commit that holds this card, named in `~/wf/runs/p2s0/COMMIT`.
* **Cluster job ids:** containers `wf-p2s0-s0`, `wf-p2s0-s1`, `wf-p2s0-s2`.   **Estimated GPU-hours:** 0 (CPU only; about
  2.5 hours per run if a round takes the 8 s of the stored runs)
